# PR03 — нода patrol: роли, опыт разрыва имени, измерения

## Роли частей кода

- **`__init__`** (конструктор `PatrolNode`): однократная настройка ноды при запуске —
  имя ноды (`super().__init__('patrol')`), поле `self.pose = None`, подписка на
  `/turtle1/pose` (сохранена как поле `self.pose_sub`, иначе сборщик мусора уничтожил
  бы объект подписки и callback замолчал), издатель `Twist` в относительный `cmd_vel`
  и таймер на 0.1 с. Ничего не выполняется в цикле — только регистрация.
- **`rclpy.spin(node)`**: бесконечный цикл обработки событий. Ждёт прихода сообщений
  и срабатывания таймера и вызывает соответствующие callback'и. Пока `spin` не
  запущен, ни один callback не вызовется, даже если подписки созданы.
- **callback**: функция, которую ROS вызывает сам по событию. `pose_callback` вызывается
  на каждое сообщение `/turtle1/pose` и по контракту задания только сохраняет
  последнее сообщение в `self.pose`; `timer_callback` вызывается таймером каждые 0.1 с,
  берёт команду у чистой функции `choose_cmd(self.pose)` и публикует её.
- **Ctrl+C**: прерывает `spin`, выполняется блок `finally` — `destroy_node()` и
  `rclpy.shutdown()`; процесс завершается, все издатели/подписки ноды исчезают из
  графа. Никакого сообщения «я умерла» топикам не отправляется.

## Запуск

```bash
# A
ros2 launch turtle_bringup sim.launch.py
# B (сбойный вариант — без remap)
ros2 run patrol patrol
# B (исправление)
ros2 run patrol patrol --ros-args -r cmd_vel:=/turtle1/cmd_vel
# C
ros2 node list --no-daemon --spin-time 2
```

После запуска `/patrol` и `/turtlesim` видны в графе (`nodes.txt`).

## До / сбой / после

**Сбой (до remap).** Нода публикует в относительный `cmd_vel`; из-заnamespace ноды
полное имя получилось `/cmd_vel` (см. `info-broken.txt`):

| Топик | Publisher | Subscription |
|---|---|---|
| `/cmd_vel` | 1 (`patrol`) | **0** |
| `/turtle1/cmd_vel` | 0 | 1 (`turtlesim`) |

Тип сообщения везде `geometry_msgs/msg/Twist`, QoS совместимы — но имена разные,
соединения нет. Поза при непрерывно работающем издателе не изменилась ни на байт
(`pose-start.txt` и `pose-after-wrong.txt`: x=5.544, theta=0.0) — черепаха стоит,
хотя «команда публикуется 10 раз в секунду».

**После (remap).** `ros2 run patrol patrol --ros-args -r cmd_vel:=/turtle1/cmd_vel` —
имя издателя переопределено на имя топика подписчика. Изменение только в имени
(код, скорость, домен не менялись). Черепаха поехала дугами (`info-fixed.txt`:
у `/turtle1/cmd_vel` издатель `patrol` и подписчик `turtlesim`;
`pose-run1.txt` → `pose-run2.txt` за 3 с: x 4.93→3.91, y 8.76→6.85,
theta −2.77→−1.35, скорости 0.5/0.3).

**Частота команды** (`ros2 topic hz /turtle1/cmd_vel`, 10 с, `hz.txt`):
average rate 10.000 Гц, min/max интервал 0.099/0.101 с — таймер 0.1 с работает точно.

## Остановка: исчезновение процесса ≠ команда торможения

До остановки — последняя сохранённая поза движущейся черепахи:
`linear_velocity: 0.5, angular_velocity: 0.3`. После Ctrl+C у patrol нулевой Twist
в `/turtle1/cmd_vel` не публиковался вообще — издатель просто исчез. В `inertia.txt`
оба замера после остановки дают одинаковые координаты и нулевые скорости: нули в
`turtlesim` появились не от patrol (ему нечем их отправить), а из внутренней защиты
симулятора — таймаута приёма команд (~1 с). Первый замер я выполнил чуть позже этого
таймаута, поэтому фазу «ещё катится по последней команде» на записи не застал —
она видна только если успеть прочитать позу в первую секунду после Ctrl+C. Вывод
от этого не меняется: исчезновение издателя ≠ команда остановки, реальная команда
торможения — нулевой Twist в топик. У «настоящего» робота без такой защиты
исчезновение издателя означало бы движение с последней командой неограниченно.
